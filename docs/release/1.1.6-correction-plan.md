# opencode-ship 1.1.6 Correction Plan, Continued as 1.1.7

Issue [#70](https://github.com/Viktorxyz/opencode-ship/issues/70) establishes
the evidence baseline for the original `1.1.6` stabilization line. The immutable
`1.1.6` tag failed in `pack` during [release workflow run
33495352417](https://github.com/Viktorxyz/opencode-ship/actions/runs/33495352417),
before npm publish or GitHub Release; no npm package or GitHub Release was
created, and the tag will not be reused. The correction continues as the active
unpublished `1.1.7` line. Each implementation slice gets its own issue,
worktree, pull request, review, verification, and explicit merge decision.

## Verified baseline

- `origin/main` is `f23191a25e758f050f7d88c13aa1312c2263305c` and declares
  package version `1.1.5`.
- npm `latest` is `opencode-ship@1.1.5`.
- The `1.1.5` package publish completed, but release workflow run
  `32373949412` failed in the GitHub Release job before the repository was
  checked out.
- The `1.1.5` tarball SHA-256 is
  `478ef3f1023facf0c0ee21eb2525e94c71797d970a2eed0eded39f8c8ca0309c`.
- `main` does not contain the installed `.opencode/` control layer,
  `opencode.json`, `AGENTS.md`, or `docs/agents/**`; self-hosting is therefore
  not complete.

These facts are the starting point, not release claims. They must be checked
again immediately before each dependent slice.

## Fixed decisions

- Automated release and self-host operations use an exact package reference:
  `opencode-ship@<X.Y.Z>`. They never execute against `@latest`.
- The package must be published and qualified before that exact version can
  bootstrap this repository.
- One issue maps to one worktree and one pull request. Published branches are
  synchronized by merging the latest default branch, never rebased or
  force-pushed.
- Dual final review, independent verification, required CI, same-HEAD binding,
  explicit merge approval, and post-merge cleanup remain mandatory.
- Documentation describes only evidence that exists. Unreleased fixes stay
  marked as planned until their gates pass.

## Delivery slices

### 1. Corrective package

Fix the GitHub Release checkout, make cleanup retry converge by persisted
stage, keep lock templates portable, exercise the root permission hierarchy,
publish a usable `opencode-ship/core` type surface, remove stale version
literals, and make `prepack` fail closed when build dependencies are absent.

Acceptance requires `npm run verify`, a successful npm publish with
provenance, a successful GitHub Release using the same release ref, and a
qualification report whose hashes agree with the published tarball.

### 2. Exact-version self-host bootstrap

After `1.1.7` is published and its integrity is checked, initialize a fresh
worktree using exactly `opencode-ship@1.1.7`. Commit the generated control
layer, complete `/setup-ship-workflow`, confirm all 32 tools are discoverable,
and run one real issue through planning, task review, dual final review,
verification, Ready, explicit merge, and cleanup.

Acceptance requires `main` to contain the self-host control layer and
`.opencode/ship.lock.json#manager.version` to equal `1.1.7`, with no
machine-local absolute template paths in the lock.

### 3. Exact-version update proposals

Add a read-only scheduled check that compares the self-host lock version with
npm metadata and opens one idempotent update issue per newer stable version.
The automation may report the exact version, integrity, shasum, and
qualification URL; it must not install packages, edit files, or auto-merge.

A maintainer reviews `diff`, applies `update` through the exact published
version, and sends the result through the normal delivery lifecycle.

## Release completion

`1.1.7` is complete only when all of the following are true:

- local verification and required CI pass on the released HEAD;
- npm `latest` points to `1.1.7` with provenance;
- the GitHub Release contains the same tarball and qualification evidence;
- the repository self-host lock is pinned to `1.1.7` with portable paths;
- OpenCode discovers the canonical 32-tool set; and
- a real self-hosted issue completes through post-merge cleanup.
