# 1.1.2 Self-Hosting Correction Plan

This plan is the authoritative execution script for `opencode-ship@1.1.2`.
It supersedes the slices claimed-complete in `1.1.1-stabilization-plan.md`
and the regression that shipped as `1.1.2-rc.1`.

`1.1.2-rc.1` is published on npm `next` but is **incomplete**: the
ship-controller never dispatches a real OpenCode session, the
setup-complete command orders state writes so that a failed validation
still removes the marker, the trusted-skill install writes a placeholder
SKILL.md, the root permission matrix is not wired, JSONC support is lost
on rewrite, and the legacy `delivery.json` adapter still wins over
`ship.config.json`. The current dogfood PR fails on a real test that
the plan deprecates. `1.1.1` is deprecated but still the `latest` tag.

## Hard Rules

- Do not promote a prerelease to npm `latest`.
- Do not overwrite or retag `1.1.2-rc.1`.
- Publish `1.1.2-rc.2` now; publish subsequent rc's only if forced.
- Do not use local `dist`, local tarballs, or `@latest` for formal dogfood.
- Do not claim dogfood from `init`, `update`, `doctor`, tool-count, or smoke tests.
- Formal dogfood must use real OpenCode, real GitHub, real models and the public plugin tools.
- Do not import `src/workflow/**` or `src/state/**` from packed qualification tests.
- Do not manually write setup docs to simulate `/setup-ship-workflow`.
- Do not manually patch generated plugins in consumer repos.
- Do not use `--replace-managed`, `--force-config`, or `--force-root-config` to hide migration conflicts.
- Do not merge with red or pending required checks.
- Do not merge a delivery PR before Ready.
- Do not bypass npm 2FA, OpenCode restart, or explicit `merge it` gates.
